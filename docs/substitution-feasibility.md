# An alternate supplier is a path with qualification and timing

Method update: October 18, 2026. Proposed experiments below are not reported as executed results.

A supplier graph can contain two suppliers while still containing one usable route to delivered output. A second foundry node may require a process redesign; another substrate vendor may lack the package specification; an alternate line may deliver after the decision horizon. Counting neighboring nodes therefore measures graph degree, not operational substitution. The current `substitutability` factor counts same-type, same-subtype peers, or every same-type company when a node has no subtype peer, which likewise measures public alternatives without qualification (see `docs/methodology.md`). The fallback scores the sole supplier of a subtype as if every same-type company were an alternative.

The existing scenario machinery in `src/lib/scenarios.ts` scales node scores, bumps edge strengths, adds lead-time months and suppresses export-controlled edges; it has no supplier cut, scenario horizon or route availability. Extend it with those before testing a synthetic dependency with an alternate route that is visible but unavailable within the horizon. Keep qualification, available capacity, allocation and switching lead time as separate assumptions. A candidate alternative should state which of those assumptions is observed and which is inferred.

The proposed acceptance case has a primary supplier cut and two alternatives: one qualified but capacity-limited, one capable but too late. The explanation should name the unresolved constraint instead of reporting full substitution. Once edges carry qualification and lead-time evidence (not modeled today), re-run the affected risk packet when that evidence changes; retain the earlier packet as a historical result. Scenario multipliers express conditional stress choices and should not be presented as event probabilities.
